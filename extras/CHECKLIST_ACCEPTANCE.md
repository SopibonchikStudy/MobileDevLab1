# Чек-лист приёмки лабораторной работы

Документ фиксирует ручную проверку сценариев, которые нельзя подтвердить только
unit-тестами: работу JokeAPI, кэш, офлайн-восстановление, UI, темы и журналы
жизненного цикла.

## Подготовка

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Перед проверкой очистите данные приложения, если нужен сценарий первого запуска:

```bash
adb shell pm clear com.example.a1lab
```

Команду очистки выполняйте только для тестового эмулятора, чтобы не удалить
нужные данные.

## Авторизация и профиль

- [ ] Первый запуск показывает бренд, поля входа и кнопку регистрации.
- [ ] Пустые и некорректные поля показывают текст ошибки.
- [ ] Регистрация с паролем менее 6 символов не создаёт аккаунт.
- [ ] Несовпадающие пароли не создают аккаунт.
- [ ] Корректная регистрация возвращает на старт и заполняет логин.
- [ ] Неверный пароль не открывает коллекцию.
- [ ] Верный пароль открывает `ContentActivity`, стартовый экран закрывается.
- [ ] Повторный запуск показывает приветствие и сохранённый профиль.
- [ ] В настройках имя и возраст сохраняются и видны после перезапуска.
- [ ] Аватар можно выбрать, сохранить и увидеть на старте, в ленте и настройках.

## JokeAPI, кэш и офлайн-режим

- [ ] При первом входе виден индикатор загрузки.
- [ ] В ленте от 12 до 20 уникальных шуток с текстом, категорией, типом и
      количеством слов.
- [ ] Список прокручивается до последней карточки.
- [ ] После перезапуска шутки открываются из кэша без обязательного запроса.
- [ ] Кнопка обновления получает новую порцию.
- [ ] При отключённой сети и наличии кэша сохранённые шутки остаются доступны.
- [ ] При отключённой сети без кэша показано понятное сообщение и кнопка
      повтора.

## Резервная копия

- [ ] В настройках при отсутствии копии восстановление и удаление неактивны.
- [ ] Создание копии требует подтверждения и показывает результат.
- [ ] После очистки коллекции пустое состояние предлагает восстановление.
- [ ] Восстановление возвращает шутки без сети.
- [ ] Удаление копии требует подтверждения и блокирует восстановление.

## Настройки и UI

- [ ] Светлая, тёмная и системная темы применяются сразу.
- [ ] Масштаб текста изменяется и заметен на экранах.
- [ ] Русский и английский интерфейсы применяются после выбора.
- [ ] Настройки сохраняются после перезапуска.
- [ ] Поворот экрана не сбрасывает критичное состояние.
- [ ] Системная кнопка «Назад» из настроек возвращает к данным.
- [ ] На экране данных случайный повторный клик не создаёт вторую Activity.

## Логи жизненного цикла

Проверка идёт в двух терминалах. В первом очистите и начните запись:

```bash
adb logcat -c
adb logcat -s Lab1Lifecycle
```

Во втором выполняйте сценарий. Сохраните вывод первого терминала в отдельный
файл отчёта. В логах должны быть строки формата:

```text
StartActivity: onCreate
StartActivity: onStart
StartActivity: onResume
```

### Стек 1: частичное перекрытие

- [ ] Открыть `StartActivity`.
- [ ] Выдвинуть шторку уведомлений.
- [ ] Вернуться в приложение.
- [ ] Сохранить последовательность `onPause`, `onStop`, затем `onRestart`,
      `onStart`, `onResume`.

### Стек 2: полный маршрут

- [ ] Открыть `StartActivity`.
- [ ] Пройти в `RegistrationActivity`, зарегистрироваться и вернуться.
- [ ] Войти в `ContentActivity`.
- [ ] Открыть `SettingsActivity` и вернуться к данным.
- [ ] Выйти из приложения через подтверждённый диалог.
- [ ] Сохранить стек, содержащий жизненный цикл всех четырёх Activity.

## Безопасность

- [ ] В Logcat отсутствуют пароль, соль, хеш и полное содержимое файлов.
- [ ] Пароль не передаётся через `Intent`.
- [ ] В настройках Android backup отключён для приложения
      (`android:allowBackup="false"`).

## Итог сдачи

К отчёту приложите два сохранённых стека Logcat, результат команды
`./gradlew assembleDebug`, а также отметки по пунктам выше.
