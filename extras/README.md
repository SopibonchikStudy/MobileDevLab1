# Punchline

Android-приложение первой лабораторной работы: коллекция шуток с четырьмя
Activity, локальной регистрацией и входом, настройками профиля, резервной копией
и журналированием жизненного цикла.

Данные загружаются с [JokeAPI](https://jokeapi.dev/). На первом запуске экран
шуток делает запрос к API, собирает от 12 до 20 уникальных двучастных шуток и
сохраняет результат в JSON-кэш. Открытие приложения повторно использует кэш;
кнопка обновления загружает новую порцию. При отсутствии сети уже загруженные
шутки открываются из кэша.

## Запуск

Откройте проект в Android Studio, дождитесь синхронизации Gradle и
запустите конфигурацию `app`. Минимальная версия — Android 7.0 (API 24).
Приложению нужно подключение к интернету для первой загрузки и обновления
коллекции. API-ключ не требуется.

Проверки проекта:

```bash
./gradlew assembleDebug
```

## Реализовано

- `StartActivity`, `RegistrationActivity`, `ContentActivity` и
  `SettingsActivity`; только стартовый экран является LAUNCHER.
- Jetpack Compose и Material 3, светлая, тёмная и системная темы, масштаб
  шрифта, русский и английский интерфейс, выбор аватара. Настройки
  сохраняются в `SharedPreferences`.
- Локальная регистрация и вход. Пароль хранится как HMAC-SHA256-хеш с
  уникальной солью; открытый пароль, хеш и соль не передаются между Activity и
  не пишутся в Logcat.
- Коллекция из 12–20 шуток с уникальным идентификатором, категорией, типом,
  текстом, панчлайном, признаком безопасного режима и количеством слов.
- `RemoteJokeRepository` выполняет HTTP-запросы к JokeAPI в
  `Dispatchers.IO`, объединяет пакеты ответа, удаляет дубликаты по API `id` и
  кэширует результат в `filesDir/jokes_cache.json`.
- `jokes_backup.json` версии 2 во внутреннем хранилище. Создание, проверка,
  восстановление и удаление копии выполняются в корутинах.
- Четыре ViewModel с `StateFlow`, одноразовые события и слои `domain`, `data`,
  `storage`, `ui`, `viewmodel`.
- Навигация через Activity Result: регистрация возвращает логин, настройки —
  логин и признак изменения профиля. Пароль через `Intent` не передаётся.
- Журналирование жизненного цикла всех Activity тегом `Lab1Lifecycle` в
  формате `ИмяActivity: метод`.

## JokeAPI

Используется endpoint:

```text
https://v2.jokeapi.dev/joke/Any?type=twopart&amount=10&safe-mode&lang=en
```

За один запрос API возвращает не более 10 шуток. Репозиторий выполняет не более
трёх пакетных запросов, пока не получит минимум 12 уникальных шуток. Запросы
идут с `safe-mode`, а сырые ответы API не попадают в Compose: преобразование в
`JokeCard` выполняет data-слой.

Тексты JokeAPI поставляются на английском языке и не переводятся. Язык
интерфейса можно переключить на русский, английский или системный в настройках.
Если API вернул ошибку, неверный JSON или меньше 12 уникальных шуток,
показывается сообщение и кнопка повторной загрузки. Если в кэше уже есть ранее
полученные шутки, они не стираются при неудачном обновлении.

## Сценарий проверки копии

1. Войти в коллекцию и открыть настройки.
2. Создать резервную копию и подтвердить действие.
3. Нажать «Очистить шутки» и вернуться к данным: появится пустое состояние.
4. Из пустого состояния восстановить копию; загруженные шутки вернутся.
5. В настройках удалить копию; восстановление станет неактивным, а новую копию
   можно создать снова после загрузки коллекции.

## Логи для отчёта

Логи снимаются командой:

```bash
adb logcat -s Lab1Lifecycle
```

Первый сценарий: открыть `StartActivity`, опустить шторку уведомлений и
вернуться в приложение. Второй: пройти регистрацию, вернуться на старт, войти,
открыть настройки, вернуться к шуткам и выйти. Для экрана шуток выход
подтверждается диалогом; системная кнопка «Назад» в настройках сразу возвращает
к коллекции.
